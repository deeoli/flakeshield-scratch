3 Core Architecture (Current Product)

Deterministic Core

  • Parse JUnit XML to canonical events
  • Normalize traceback/message into stable fingerprints
  • Group failures deterministically
  • Detect flaky tests across runs
  • Compute explainable confidence
  • Remain authoritative at all times

Semantic Advisory Layer

  • Embed failure text
  • Known vs novel classification
  • Historical similarity lookup
  • Semantic failure grouping
  • Risk enrichment only
  • Optional, gated, non-blocking

Decision Intelligence

  • Risk scoring
  • Risk tiers: LOW / MEDIUM / HIGH / CRITICAL
  • Regression detection (latest vs previous run)
  • Policy flags: warn/fail/threshold
  • CLI high-risk summary
  • PR summary generation

State Layer

  • SQLite as source of truth
  • test_results authoritative table
  • failure_embeddings for semantic memory
  • Idempotent inserts
  • History-backed analysis
  • Postgres planned later for hosted mode

4 Data Model (Current + Near-Term)

Store / TableKey FieldsPurpose
test_results run_id, test_id, status, message, traceback, fingerprint Canonical run history; deterministic source of truth
failure_embeddings fingerprint, model_name, dim, vector, created_at Persist semantic memory for known/novel and similarity lookup
reports (derived) JSON, Markdown, PR comment markdown Presentation layer over stored DB state
future trends first_seen, last_seen, risk trend, flake trend Planned multi-run health and multi-repo analytics

Guarantee: Reports are views over persisted DB truth. Deterministic logic always runs; semantic logic may enrich but never replace it.

5 Product Flow

Ingestion + analysis flow:

JUnit XML → CLI / GitHub Action → Canonical Events → Fingerprinting → SQLite Persistence → Risk / Regression / Policy → Reports + PR Summary

Policy flow:

Risk tiers → warn-on-high → fail-on-critical → max-risk-threshold

Distribution flow:

CLI → GitHub Action → Docker runtime → Future hosted platform

7 Roadmap Layers

Layer 1 — Engine

Deterministic grouping, flaky detection, semantic assist, scoring, contract freeze.

Layer 2 — Product

Packaging, config, policy flags, PR summary, action wrapper, Docker runtime.

Layer 3 — Runtime

External validation in a separate repo, artifact upload, PR comment flow, action hardening.

Layer 4 — Distribution

Release, Marketplace-grade action, example repos, reusable adoption path.

Layer 5 — Platform

Hosted ingestion, multi-repo aggregation, trends, notifications, team settings.

Layer 6 — FlakeShield Plus

Dashboard, governance, org-wide CI reliability control, later explanation layer.

Rule: the roadmap compounds from reliable intelligence → CI product surface → runtime validation → distribution → platform. It does not jump straight to dashboards or LLM layers.
